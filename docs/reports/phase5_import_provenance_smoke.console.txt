1. STEPS 1-3 -- ROUTE SURFACE WITH THE FLAG OFF
--------------------------------------------------------------------------------
All 15 routes probed over HTTP with HORNELORE_IMPORT_PROVENANCE unset.
42 probes total (each body-taking route x {well-formed, {}, junk, no body}).

    Result: 404 on every probe. 0 schema leaks.

This is the check that caught the Phase 4 gate defect. Before the fix,
POST /batches and POST /candidates/{id}/decision answered 422 with the names
of their required fields while the flag was off -- disclosing that the route
existed and what its schema was. Cause: FastAPI validates the request body
before it calls the handler, and the gate was the first line INSIDE each
handler, so a malformed body never reached it.

Fix (applied in this phase, in server/code/api/routers/import_provenance.py):
the gate became a router-level dependency, which is solved before body
validation, so the 404 wins.

    router = APIRouter(
        prefix="/api/import-provenance",
        tags=["import-provenance"],
        dependencies=[Depends(_require_enabled)],
    )

The per-handler _require_enabled() calls were kept so each handler stays
correct on its own. Two tests added in tests/test_import_provenance_routes.py
inside FlagGateTests:
    test_every_route_404s_when_the_flag_is_off_and_the_body_is_junk
    test_the_gate_is_a_router_dependency_not_only_a_handler_call

FINDINGS
--------------------------------------------------------------------------------
FINDING 1 -- the one FAIL was the test, not the product.
    match_reason is stored via json.dumps(..., sort_keys=True) in
    import_repository.py, so keys come back alphabetized. The assertion used
    an order-sensitive JSON.stringify comparison. A deep-equal comparison
    passes: every key, nested object, float and array element round-tripped
    exactly. Sorting is deliberate -- it makes the stored JSON stable and
    diffable. No product change. The assertion is the thing that was wrong.

FINDING 2 -- stored_rejected_count = 2 while live rejected = 1. Correct.
    _refresh_batch_counters counts 'rejected' AND 'duplicate' into the
    schema's rejected_count column. batch_counts() deliberately returns both
    the live per-state counts and the stored counters "so a caller can see if
    the two ever disagree." They do not disagree; they measure different
    things. Counters are recomputed from the candidate rows, never
    incremented, and hidden candidates still count -- hiding is retirement
    from a view, not a claim the import never happened.

FINDING 3 -- venv drift between the test harness and the serving stack.
    Recorded in Chris's words:

    "The unittest route suite ran under .venv, while the serving API used
    .venv-gpu with older FastAPI/Starlette. The Phase 5 smoke therefore
    verified the serving version directly. Dependency alignment belongs in
    a later harness/environment work order, not inside Import Provenance
    Phase 5."

    Deferred. Not a Phase 5 item.

FINDING 4 -- the 422 gate defect and its fix. Found and fixed in this phase.
    Detail in section 1 above. This was a real information disclosure while
    the flag was off, and it is the reason the flag-off probe set was
    widened to include malformed and empty bodies.

FINDING 5 -- Chrome throttles backgrounded tabs.
    Per-request latency measured through the browser reached 75-120s, while
    api.log showed the server answering the same requests promptly. The
    stack was never slow. Consequence for anyone repeating this: batch the
    whole smoke into one payload rather than one request per round trip.
    A single transient "TypeError: Failed to fetch" on the first POST of the
    first attempt was handled by adding a 4 x 2s network retry; the green
    run used exactly one retry.

FINDING 6 -- deliberate deviation, disposable context.
    Batch A is Christopher's rather than a synthetic person, because all
    four photos in the database are his and the accept step requires a
    same-person photo. Mitigations and proof in section 3 and section 5.

FINDING 7 -- pre-existing, not touched.
    tests/ has cross-module contamination; `python3 -m unittest discover -s
    tests` is not a usable gate. pytest is not installed. Modules must be run
    individually. Recorded, not worked -- outside the Phase 5 scope wall.
