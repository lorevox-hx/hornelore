## 0. The 60-second orientation

**Hornelore is Lorevox.** A privacy-first, local-first conversational memory
system for older adults. The Horne family (Chris + parents Kent & Janice) is
*tenant zero*, not a special case. Two product surfaces matter right now:

1. **Lori** — the narrator-facing story listener. A nine-stage deterministic
   runtime pipeline; the LLM is one stage. Dementia-safe, no-correction,
   listen-first. Safety is deterministic + an LLM second layer.
2. **Travel Doc Lab** — the *operator* workspace for turning a trip's photos,
   notes, and sources into a travelogue. This is the **active build lane**.

The hard line between them is sacred: **operator tooling never touches
narrator state, and narrator-facing output never leaks operator/machine-guess
evidence as fact.** Most of the guardrails in this codebase exist to enforce
that line.

## 1. What just landed (2026-07-24) — the Travel Doc Draft Assistant

The Lab could gather and approve evidence but couldn't *produce* anything.
Now it can. `WO-TRAVEL-DOC-OPERATOR-DRAFT-ASSISTANT-01` is **landed and
live-validated**.

**What it does:** operator picks a scope (whole trip / region / stop) in a new
**Draft** tab → the assistant assembles the approved evidence already gathered
→ drafts a travelogue paragraph → operator edits it → "Keep as draft note"
stores it as a non-promoted draft. Nothing auto-promotes to the memoir.

**Files:**

| Piece | File |
|---|---|
| Inference wrapper (operator-side) | `server/code/api/llm_interview.py` → `draft_travel_section()` |
| Assembly service (LAW-3 isolated) | `server/code/api/services/trip_draft.py` |
| Endpoint | `POST /api/trips/{trip_id}/draft-section` in `routers/trips.py` |
| Lab UI | `ui/js/travel-doc-lab.js` (`renderDraft` + `_draft*` helpers), `ui/css/travel-doc-lab.css` (`.tdl-draft-*`) |
| Tests | `tests/test_trip_draft.py`, `tests/test_trip_draft_isolation.py`, `tests/test_travel_doc_lab.py::DraftAssistantTest` |

**Locked doctrine (do not regress):**

- **Reuse `build_travelogue_outline()` for evidence** — do not re-implement
  evidence assembly. The builder already filters rejected public context,
  excludes raw GPS, labels machine guesses `(draft)`, and keeps unpromoted
  notes out of the block. `trip_draft` inherits all of that for free.
- **Approved evidence may be stated plainly; draft evidence is included but
  written suggestively** ("appears to", "seems to"). This mirrors the
  builder's no-invention rule. The split is enforced in `_evidence_text()`
  and the `draft_travel_section` system prompt.
- **Unpromoted notes are excluded unless explicitly selected** via
  `include_note_ids`. Same for sources. Promoted (`include_in_memoir=1`) is
  the default inclusion.
- **`MODSAVE-*` sentinels are dropped** from context (`_SENTINEL_RX`).
- **Nothing persists on `/draft-section`.** Keep writes a `trip_location_notes`
  `source_type='draft'` row with `include_in_memoir=0` **and**
  `include_in_interview_context=0`. The operator promotes by hand later.
- **LAW-3 isolation:** `trip_draft.py` imports only `trip_repository`,
  `travelogue_builder`, `evidence_text`, `llm_interview`. The build-gate
  `test_trip_draft_isolation.py` fails if `chat_ws` / `prompt_composer` /
  `extract` ever appear. Inference goes through `llm_interview` (raw
  `api.chat()`), never the narrator WebSocket/composer.

**Live validation (Spring 2026 trip, Prague region):** preview returned 3
approved operator anchors with no unpromoted notes leaking; a ~5s draft stayed
within evidence (Prague, May 22 2026, Czechia's capital); Keep created the
correct draft note. All 10 of Chris's acceptance tests pass in unit tests and
live.

**Known quality gap (candidate next task):** on *thin* evidence the model
reaches for details that aren't there — twice it invented arrival "by train"
and a "bustling station" for Prague. It is narrative color, not a fabricated
proper-noun/date/price, so it's within the no-invention letter — but tighten
the `draft_travel_section` system prompt with an explicit "do not invent the
mode of arrival or transitions not in the evidence" clause when you next touch
it.

## 2. The map — what already exists in the trip/travel lane

Do not rebuild these. Study them first (Chris's standing instruction: *"study
all of the travel and trip so you don't miss what is there already"*).

**Services** (`server/code/api/services/`):

- `travelogue_builder.py` — **the evidence-assembly engine.** Read-only,
  no LLM, no web. Produces ordered blocks (Region Chapter / Itinerary Tile /
  Discovery Tile / Sensory Coda) with labeled `prose_anchors`, provenance
  badges, per-block `llm_prompt`, and an `intake_review` bucket for
  unpromoted notes. **Everything downstream should read from this.**
- `trip_draft.py` — the new Draft Assistant (see §1).
- `travel_doc_lori_modal.py` — the operator "Talk with Lori about this photo"
  modal path. Approved/draft packet semantics live here and in the builder.
- `travel_doc_photo_ocr.py`, `travel_doc_photo_vision.py`,
  `travel_doc_public_lookup.py` — evidence *acquisition* (OCR, draft vision
  observations, URL-only public lookup with SSRF guard).
- `trip_repository.py` — all trip CRUD + the canonical row accessors.
- `trip_memoir_docx.py` — deterministic DOCX export (Part I/II/III + photo
  appendix). **Does not yet harvest `story_candidates`** — see §3.
- `trip_photo_clustering.py`, `photo_intake/*` (EXIF, filename dates,
  metadata trust, geocode, dedupe) — photo ingest + spacetime clustering.
- `trip_interview_context.py`, `trip_story_capture.py`,
  `trip_narration_capture.py` — the narrator-side trip loop (Travels shelf →
  Lori → candidate notes). Separate from the operator Lab.

**Routers:** `routers/trips.py` (huge — the trip API), `routers/photos.py`,
`routers/memoir_export.py`.

**UI:** `ui/travel-doc-lab.html` + `ui/js/travel-doc-lab.js` (the experimental
operator Lab — REMOVABLE by design), `ui/travel-documenter.html` +
`travel-documenter.js` (the production operator panel), `ui/js/travels-shelf.js`
(narrator-side). The Lab and the production panel are separate; keep their
state separate.

**Inference path (operator-side):** `server/code/api/llm_interview.py` —
`_try_call_llm` (raw `api.chat()`), `draft_section_summary`,
`propose_followup_questions`, `draft_final_memoir`, and now
`draft_travel_section`. This is the sanctioned non-narrator LLM path.

  The agent sandbox mount is live on Chris's repo (edits are real). The

- **Git:** the sandbox cannot run git. Produce copy-paste `git add <specific
  paths>` + `git commit` blocks for Chris (never `git add -A`/`.`, never
  include `git push` — he pushes from GitHub Desktop). One logical commit per
  block. Tree must be clean before code work.
- **Stack:** Chris starts/stops the stack himself. Cold boot ~4 min (listener
  up in ~70s, then model warmup). Backend/`.env` changes need a restart;
  frontend changes are reload-only. Batch accordingly.
- **Safety is load-bearing.** `safety.py` (deterministic patterns) +
  `safety_classifier.py` (LLM second layer) + the `chat_ws` hook + the
  response guards (`lori_response_guards.py`) protect an 86-year-old narrator.
  Never route the Draft Assistant or any operator tool through the narrator
  path. Never disable a guard behind a broad `except`. (See INC-2026-07-09:
  guards were silently dead for 5 days because a regex `re.error` was swallowed
  by a per-turn `try/except` — structural failures must fail the boot, not
  degrade silently.)
- **Tests are the contract.** The isolation build-gates
  (`test_trip_draft_isolation.py`, `test_travel_documenter_panel.py`,
  `test_utterance_frame_isolation.py`, `test_story_preservation_isolation.py`)
  mechanically enforce the operator/narrator boundary. When you add an
  operator tool, add its isolation gate. Verify a negative test (inject a
  forbidden import → gate FAILS → remove → PASSES).
- **No native dialogs in the Lab** (`window.prompt/confirm/alert` are banned —
  use in-panel drawers). **No-delete posture** on evidence (mark `rejected`,
  never DELETE; approved rows are never touched by supersede/cleanup).
- Prefer editing real files over showing code. Read files fully before editing
  (a past miss came from patching around an unread branch).

## 5. Gotchas discovered this session

- `evidence_text.sanitize_for_prompt()` defaults to **240 chars** — fine for a
  single field, far too small for an assembled evidence bundle. `trip_draft`
  passes `max_chars=6000`. Watch for this if you assemble prompts elsewhere.
- Region-scope note/source filtering must include the region's **stop** rows,
  not just direct region rows — but must not pull stops from *other* regions.
  `trip_draft._in_scope` + `_region_stop_ids` handle this; the naive filter
  leaked cross-region stop notes (caught by a test).
- A UI auto-load-on-render that re-fetches whenever its data is null will
  **infinite-loop on error** (preview stays null → re-fetch every render). Use
  a "tried" flag. (Fixed in `renderDraft` via `d.previewTried`.)
- The Claude-in-Chrome extension drops its connection on navigation
  occasionally; re-create the tab group (`tabs_context_mcp{createIfEmpty}`) and
  re-navigate to a localhost page before running `fetch` against the API.
- Stale data: `MODSAVE-<digits>` strings can appear in region summaries (a save
  sentinel that leaked). The Draft Assistant excludes them; clean the row with
  `PATCH /api/trips/regions/{id}` `{clear_summary:true}`. "Braveria" (should be
  "Bavaria") is a stored region-title typo on the Spring trip — display-only
  normalization exists for Lori's directive, not the operator outline.
